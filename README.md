# Горн

Трекер валюты и фарм-эффективности для **Torchlight: Infinite**. Интерфейс
на русском и английском.

Читает клиентский лог игры и показывает, сколько ФЕ приносит твой фарм —
честно, с оценкой достоверности, а не одним усреднённым числом. Поверх игры —
компактный оверлей, всплывающий доход и подсказки в сезонной тюрьме.

**[Скачать последнюю версию →](https://github.com/lanqvist/gorn-tli/releases/latest)**
· Windows 10/11 · установщик или портативный `.exe` · поддерживает SS14 Tartarus

---

## Что умеет

- **ФЕ в час по медиане** с разбросом P25–P75, размером выборки и
  предупреждением, если цифра держится на одной находке.
- **Стратегии без разметки**: забеги группируются по тому, чем открывалась
  карта, — вложения видны в логе поштучно.
- **История с первого запуска**: Горн разбирает все логи, которые игра уже
  накопила, и сохраняет их, пока игра их не удалила.
- **Цены сразу**: первичные цены приезжают из базы сообщества, ваши пробивки
  в Торговом доме ложатся поверх. Тренд цены за неделю, исключение предмета
  из учёта, стоимость сумки.
- **Реальная выручка биржи**: сколько ФЕ дошло до кармана против бумажной
  оценки лотов.
- **Карты, история, поиск**: сводка по картам с игровыми названиями, история
  по дням и сессиям, поиск по всем забегам, экспорт в CSV для Excel.
- **Персонажи и сезоны**: каждый забег записан на своего героя и свой сезон,
  прошлые сезоны оцениваются ценами своего сезона.
- **Оверлей «Сводка»** поверх игры, пропускающий клики, и **всплывающий
  доход** у центра экрана: «+N ФЕ», золотые плашки, итог карты.
- **Звук «Подпись»**: что упало, слышно не глядя на экран.
- **Подсказки в тюрьме Талоса** (SS14): стрелка к лучшему ходу по своему
  симулятору. Выключены по умолчанию.

## Чем отличается от других трекеров

| | Горн | TITrack, Fenix, Exile Diary и прочие |
|---|---|---|
| Главная метрика | **медиана** + разброс P25–P75 + размер выборки | среднее арифметическое |
| Предупреждение «цифра держится на одной находке» | есть | нет |
| История из уже накопленных логов | **читает старые логи при первом запуске** | начинают с нуля |
| Первичные цены | **приезжают сами** из базы сообщества + свои пробивки поверх | каждый предмет пробивать руками (TITrack: опциональный клауд) |
| Учёт вложений в карту | поштучно, включён по умолчанию | константа на карту либо выключено |
| Реальная выручка с биржи | считается (коэффициент реализации) | только бумажная оценка по ценам лотов |
| Язык | русский и английский | китайский / английский |
| Устойчивость к смене сезона | категория лога не зашита, экран самодиагностики | ломается, молча показывает нули |

Про среднее подробно: дроп в ARPG — распределение с тяжёлым хвостом. Одна редкая
дорогая вещь задирает среднее так, что оно перестаёт описывать типичный забег.
Игрок принимает решения по числу, которого не увидит ни в одном забеге.

## Установка

На [странице релизов](https://github.com/lanqvist/gorn-tli/releases/latest)
два файла:

- `Gorn-<версия>-setup.exe` — установщик, ярлыки в меню «Пуск» и на рабочем столе,
  права администратора не нужны;
- `Gorn-<версия>-portable.exe` — запуск без установки.

Windows покажет предупреждение SmartScreen: сборка не подписана сертификатом,
он стоит денег и на работу не влияет. «Подробнее» → «Выполнить в любом случае».

Steam-установка игры находится сама. Для остальных — «⚙ → Данные → Указать
папку…»: подходит и корень игры, и сама `Saved\Logs`. Пока игра не найдена,
поиск повторяется автоматически.

Для оверлея и плашек **игра должна работать в безрамочном или оконном
полноэкранном режиме**. Эксклюзивный полный экран минует оконный композитор
Windows — поверх него не может рисовать никакое приложение.

**Установленная версия обновляется сама.** О новой версии приложение сообщает
полосой сверху; загрузка и перезапуск — только по кнопке, потому что
перезапускать трекер посреди фарма недопустимо. Если просто закрыть
приложение, обновление применится при следующем запуске. Проверка идёт
при старте и дальше раз в четыре часа; кнопка «Проверить обновления»
есть в настройках.

Портативная версия себя не обновляет: она лежит одним файлом там, куда её
положили, и подменять его под руками неправильно — она может быть на флешке
или в папке только для чтения. О новой версии она сообщит, скачать нужно самому.

## Как это работает

Игра сама пишет `UE_game.log`. Горн его читает — и всё:

- **память не читается, инжекта нет, с клиентом не взаимодействуем**;
- ввод не автоматизируется, биржа не скрейпится.

Исключение — [подсказки в тюрьме](#подсказки-в-тюрьме): они выключены
по умолчанию и только при включении берут кадры с монитора, на котором игра.

```
…\Torchlight Infinite\UE_game\TorchLight\Saved\Logs\UE_game.log
```

Из лога извлекается:

| Что | Строка лога |
|---|---|
| Изменение слота сумки | `BagMgr@:Modfy BagItem PageId = 102 SlotId = 0 ConfigBaseId = 100300 Num = 6655` |
| Снимок сумки | `BagMgr@:InitBagData …` |
| Смысл транзакции | `ItemChange@ ProtoName=PickItem start` |
| Вход в зону | `LevelMgr:_EnterLevelSuccess() 5348` |
| Название карты | `LevelMgr@:LevelPath, Model = Content/Art/Maps/…` |
| Персонаж и сезон | сокет-дамп `GetPlayerData` |
| Цены с биржи | `----Socket RecvMessage STT----XchgSearchPrice----SynId = 96` |

### Две тонкости, на которых ломаются наивные реализации

**1. `Num` — это размер стака целиком, а не прирост.** Реальная последовательность
одного слота: `6611 → 6616 → 6649 → 6650 → 6653 → 6655`. Доход тут +44 ФЕ,
а сумма значений дала бы 33 223. Считаем дельту по ключу `(PageId, SlotId)`
с обработкой смены предмета в слоте, очистки слота и полной пересинхронизации.

**2. Категория лога меняется каждый сезон.** До SS12 было `GameLog:`, с SS12 —
`TLLua:`, `TLShipping:`, `TLNetGame:`. Инструменты с жёстко зашитой категорией
перестают видеть лог целиком и тихо показывают нули. Мы матчим любую категорию
и выводим экран самодиагностики. Так же с путями карт: с SS14 сезонные зоны
лежат в собственном дереве ассетов `Content/Art/Season/S16/Maps/…`, и имя
карты берётся из папки с `.umap`, а не с фиксированной глубины.

### Простой не засчитывается

Отошёл на десять минут, не выходя из карты — знаменатель вырос, числитель нет,
и любая цифра «в час» тихо занижена. Игра при этом продолжает писать в лог,
поэтому активность файла признаком не является: время считается по событиям
добычи, а паузы длиннее трёх минут в зачёт не идут.

## Возможности подробно

### Стратегии

Стратегия определяется **автоматически** — по тому, чем открывалась карта.
По каждой стратегии показывается медиана ФЕ/час, разброс, средние вложения
и средняя чистая прибыль с карты.

Для сравнения нужны хотя бы два забега в стратегии, и рядом с каждой цифрой
стоит размер выборки: две стратегии по три забега сравнивать бессмысленно,
и это должно быть видно, а не подразумеваться. Над карточками — полосы
медиан с усами P25–P75: стратегия с малой выборкой рисуется тоньше
и прозрачнее, доверие закодировано прямо в геометрию.

### Забеги, карты и история

- **Прошлый забег раскрывается**: добыча, вложения в карту, чем открывалась.
- **Поиск по всей истории** — по названию карты на любом языке или по
  предмету, выпавшему или вложенному; «без вложений» тоже находится.
- **Сводка по картам** с игровыми названиями на русском и английском:
  забеги, ФЕ в час, доход за карту, время карты и метка лучшей. Лог хранит только внутреннее имя сцены, а одну
  сцену используют разные зоны, поэтому название берётся из справочника
  `data/maps.json` по сцене и номеру уровня, а не угадывается по пиньиню.
- **История по дням и сессиям**.
- **Экспорт в CSV** для Excel — время, карта, стратегия, добыча, вложения,
  чистыми; с учётом фильтра по персонажу. Разделители подстраиваются
  под язык: в русском Excel `;` и дробная запятая.

### Сессии и персонажи

Кнопка «⟲ Новая сессия» под плитками начинает отсчёт счётчиков заново:
«За сессию», «На картах», «Вложено» и цель в оверлее. Удаления при этом
нет вообще — прошлые забеги остаются в базе, в истории и в медиане,
а итог прошлой сессии остаётся строкой рядом с кнопкой. Медиана и
стратегии сбросом намеренно не трогаются: это статистика, а не счётчик,
и резать её выборку каждым вечером жалко.

Трекер видит из лога, каким персонажем вы зашли, — ник, класс и уровень
показываются в шапке, и каждый забег записывается на своего персонажа.
Если персонажей несколько, в шапке появляется фильтр «SS14 · все персонажи /…»:
у разных героев разные билды и дроп, и смешивать их медианы — то самое
среднее по больнице.

### Сезоны

С началом сезона экономика обнуляется: цены, медиана, стратегии прошлого
сезона описывают другую игру. Поэтому по умолчанию трекер показывает только
текущий сезон — его название («SS14 Tartarus») стоит в шапке, номер берётся
из профиля персонажа в логе. Прошлое никуда не девается: в том же фильтре
есть «Все сезоны» и персонажи прошлых сезонов с пометкой «SS13».

Цена прошлого сезона в оценку текущего не попадает, даже если сообщество
предмет ещё не знает, — старая цена хуже, чем никакой. И наоборот: в «Все
сезоны» каждый забег оценивается ценами своего сезона — своими пробивками
того сезона и базой сообщества за тот же сезон (она скачивается один раз и
лежит в отдельном кэше). Медиана SS13 остаётся медианой SS13, а не
пересчётом старой добычи по ценам SS14. «Пробить цену» и блок «Цены» —
только про текущий сезон: рынок прошлого закрыт.

**Сезонная зона SS14** (тюрьма Талоса) открывается не через обычный
`Spv3Open`: кнопка старта сезонной механики списывает 2–3 «Оковы»
(Darkiron Shackles) серверной операцией `Push2`, а через пару минут
открывается зона. Такое списание засчитывается вложением в зону — иначе
она выглядела бы бесплатной. Заходы с ежедневной сезонной доски оков
не тратят и честно идут «Без вложений». Каждый заход — отдельный забег.

### Откуда берутся цены

Два источника, в строгом порядке приоритета:

1. **Ваши собственные пробивки в Торговом доме.** Игра пишет в лог цены всех
   активных лотов при каждой пробивке — они точнее всего: с вашего сервера
   и на текущую минуту. Своя цена считается свежей три дня, дальше
   уступает базе сообщества, если та новее.
2. **База сообщества TITrack** ([titrack.ninja](https://titrack.ninja)) —
   агрегированные пробивки других игроков, ~2000 предметов текущего сезона,
   обновляются каждые несколько минут. Благодаря ей трекер показывает
   осмысленные цифры с первой минуты, без ручной пробивки каждого предмета,
   валюты и компаса.

Референсной из пробивки считается цена 10-го перцентиля: минимум — это чей-то
демпинг, среднее задирают лоты, которые никто не купит.

Цены сообщества помечаются в списке дропа пунктиром; своя пробивка молча
заменяет такую цену. Опрос базы — раз в 15 минут с локальным кэшем: без
интернета трекер работает на кэше, а выключается источник одной галкой
в настройках — останутся только свои пробивки.

База принадлежит проекту TITrack (MIT, анонимное чтение — штатный режим,
на нём работает их сайт). Мы читаем её аккуратно: полная выборка один раз,
дальше только дельта. Спасибо им.

Рядом с ценами:

- **Блок «Цены»** — спарклайн и тренд за неделю по вашим пробивкам.
- **Что пробить следующим** — предметы без цены, отсортированные по тому,
  сколько их выпало: важно не количество, а какие из них портят оценку.
- **Исключить предмет из учёта** — например, то, что вы никогда не продаёте.
- **Порог мелочи** — скрывает копеечные строки из списков добычи (только
  отображение, в доход они идут).
- **Стоимость сумки** — сколько стоит то, что сейчас лежит в инвентаре.

### Реальная выручка

Отдельно считается **коэффициент реализации**: сколько ФЕ реально пришло
по отношению к бумажной оценке выставленного товара. На тестовых данных
вышло 717 ФЕ бумагой против 508 ФЕ живыми — 71%. Разрыв складывается
из комиссии биржи и продажи ниже референса.

Весь жанр, включая poe.ninja, оценивает добычу по ценам активных лотов,
то есть по бумаге. Сколько из этого доходит до кармана — не показывает никто.

Ограничение: сокет-дампы игра пишет только для `GetPlayerData`
и `XchgSearchPrice`. У поступления денег нет пометки, за какой предмет оно
пришло, поэтому коэффициент считается за период целиком, а не по предметам.
Выдумывать атрибуцию мы не будем.

### Оверлей поверх игры

Колонка «Сводка»: сверху чип с таймером и картой («в городе», «нет игры»),
под ним главная цифра — доход забега на карте или итог сессии в городе,
ниже строки с иконками, находки по ступеням и цель сессии.

| Сочетание | Действие |
|---|---|
| `Ctrl+Alt+G` | показать или убрать оверлей |
| `Ctrl+Alt+L` | закрепить / открепить |
| `Ctrl+Alt+M` | переключить режим: минимальный → компактный → подробный |
| `Ctrl+Alt+P` | снять кадр тюрьмы вручную |

Закреплённый оверлей **пропускает клики в игру** и **уходит с дороги сам**:
навели курсор — панель плавно гаснет и возвращается через полсекунды.
Открепите, чтобы перетащить: появится полоска с кнопками. Позиция запоминается
вместе с монитором и подрезается по рабочей области, чтобы оверлей
не оказался за пределами экрана после отключения монитора.

Первый раз оверлей появляется откреплённым и со шпаргалкой — иначе про
перетаскивание, режимы и закрепление узнать было бы неоткуда.

Задайте **цель сессии** в настройках («хочу 5 000 ФЕ») — оверлей покажет
тонкую полосу прогресса и оценку «ещё ~40 м» по текущему темпу.

Рядом с доходом текущего забега — **тень прошлого**: сколько предыдущий
забег имел к этой же секунде. Гонка с собственной тенью, как ghost-car
в гонках; оценка грубая и помечена тильдой.

Окно подгоняется по высоте содержимого. Это не косметика: прозрачное окно
заставляет композитор идти по дорогому пути, и лишняя пустая прозрачная
площадь стоит кадров игре.

Два известных ограничения:

- Горячие клавиши могут не доходить до приложения, пока фокус держит игра.
  Обойти это можно только низкоуровневым хуком клавиатуры — тем же примитивом,
  что у кейлоггеров. Для игры с непредсказуемым анти-читом это плохой размен,
  поэтому используется штатный механизм Electron.
- Клики пропускаются сквозь окно целиком: частичной прозрачности для кликов
  в Electron нет. Поэтому интерактивные элементы появляются только
  в откреплённом состоянии.

### Всплывающий доход у центра экрана

Отдельный слой поверх игры — как floating combat text, а не строка в панели:
чуть выше середины экрана, по центру, клики пропускает всегда. Подобрал
добычу — всплывает крупное **«+N ФЕ»**; дорогая вещь получает **золотую
плашку** с иконкой и названием. Порог золотой плашки — числом или «авто»:
дорогим считается предмет из топ-5% известных цен сезона, и порог дрейфует
вместе с экономикой.

Подборы в течение секунды схлопываются в одну плашку с растущей суммой —
лут-пылесос после босса не превращает экран в стену текста. Закрытие
карты — карточка с итогом: сумма, время, отклонение от вашей медианы
и топ-3 находки с иконками. Момент между картами — единственный, когда
игрок готов читать, поэтому подробности живут именно там.

Вторая дорогая находка подряд высекает из плашки искры, а забег
с лучшим темпом сессии встречают монетным дождём и самым полным звуком —
не чаще раза в час, чтобы рекорд оставался рекордом.

Большую часть времени окно слоя буквально не существует для композитора —
оно показывается только на время плашек.

### Звук

Звук — «Подпись»: один фирменный звук дорогой находки, и все ступени
выведены из него, как в фильтрах добычи PoE — что упало, слышно не глядя
на экран. Подбор — короткий тон, ценный — тон с коротким вздохом, предмет
дороже порога (по умолчанию 10 ФЕ) — свист, подпись в миниатюре, золотая
находка — полная подпись, вторая подряд и рекорд — подпись с квинтой
и октавой. Итог карты — квинта, разрешающаяся в тон, в минус — низкий тон
проседает и глохнет. Громкость растёт лесенкой: подбор тише всех, рекорд
громче всех.

Звон не сыплется очередью: подборы за пару секунд копятся и звучат одним
ударом с весом накопленного, а мелочь дешевле 1 ФЕ не звенит вовсе.
Режим «только важное» оставляет свист, золотую находку и итог карты.

Звуки — наши собственные: их заранее рендерит офлайн-генератор (`src/sfx`,
`npm run sounds`) из синусов и отфильтрованного шума, без сэмплов из игр
и библиотек. Характер подписи подобран по замеру реального оповещения
в ARPG — огибающая, баланс полос, строй обертонов, — но сам звук синтезирован
с нуля. Каждый файл не громче прежнего звука своей ступени ни по пику,
ни по громкости, ни по полной энергии — это проверяют тесты.

### Подсказки в тюрьме

В сезонной тюрьме (SS14, «Тюрьма Талоса») Горн рисует поверх игры стрелку
к лучшему ходу: от надзирателя к камере, рамку на нужной двери, карточке
«Пожирание / Заменить / Завершить», орудии или подарке, а рядом — короткую
причину («· событие», «· цепочка к призматическому», «· дальше невыгодно»).
Ходы делаете вы сами — ввод не автоматизируется.

Как это устроено: по строкам интерфейса тюрьмы в логе (`S16Board…`,
`[S16LastDay]`, `UI_S16_Card_Up`) Горн понимает, что экран сменился, берёт
кадр из потока монитора с игрой (снимок окна игра отдаёт чёрным), как
только картинка успокоилась, и в отдельном процессе с пониженным
приоритетом:

- **распознаёт экран** — доску, камеры, надзирателя, двери, ряд решений,
  цепочку пожирания, панель орудий, выбор орудий и подарков, выбор добычи
  «Выслеживания» (около 5 мс на кадр);
- **ведёт память забега** — орудия, цель, тему забега, день, хранилище,
  что было за дверями: то, чего не видно на одном кадре;
- **считает ход** своим симулятором: движок правил тюрьмы по таблицам клиента
  игры и стратегия с проверкой вариантами — каждый ход доигрывается до конца
  забега на одних и тех же костях. Совет появляется в среднем через 0,1 с
  (не дольше 0,3 с), потом досчитывается, пока он на экране, и меняется
  только если новый ход заметно лучше.

Правила, шансы и устройство симулятора — в
[docs/prison/rules.md](docs/prison/rules.md) и
[docs/prison/architecture.md](docs/prison/architecture.md).

Снимки никуда не уходят. С настройкой «Сохранять кадры» каждый кадр ложится
PNG в «Изображения → Горн — тюрьма → дата», а рядом JSON: строки лога и
показанная подсказка — для разбора ошибок. Папка чистится сама: картинки
кадров с подсказкой — через 2 часа, сбоев и ручных кадров — через неделю,
не больше 1 ГБ.

- Включается в настройках: «Подсказки в тюрьме». По умолчанию выключено.
- Игра — в режиме «окно без рамки» на весь монитор.
- `Ctrl+Alt+P` — снять кадр вручную, если автоматический не сработал.
- Событие пропустить нельзя, поэтому на его окне совета нет. Незнакомая
  иконка орудия совет не ломает — он считается без этого орудия.

### Настройки

Все ручки собраны в одной панели — кнопка ⚙ в шапке:

- **Звук**: все находки / только важное / без звука, громкость
  с пробным подбором, порог свиста (5–100 ФЕ или выключен) и кнопки
  прослушивания каждого звука;
- **Плашки поверх игры**: всплывающий доход и порог золотой плашки;
- **Оверлей**: прозрачность, масштаб, цель сессии, шпаргалка горячих клавиш;
- **Язык**: интерфейс (русский / английский), названия предметов
  (Рус / Eng / Оба — часть игроков ищет по английским названиям в гайдах
  и на бирже) и цены сообщества;
- **Данные**: папка логов;
- **Подсказки в тюрьме**: включение и сохранение кадров;
- **Система**: запуск вместе с Windows, «закрывать в трей» (трекер
  и оверлей продолжают работать фоном) и проверка обновлений.

## Разработка

```bash
npm install
npm start         # сборка и запуск
npm run dev       # горячая перезагрузка интерфейса
npm test          # 439 тестов, включая проверки на подлинных фрагментах лога
npm run typecheck
npm run dist      # установщик и портативная версия в release/
```

Интерфейс открывается и в обычном браузере (`npx vite`) — без main-процесса
он показывает демо-данные, чтобы вёрстку можно было проверять без Electron
(`?lang=en` — английский). При `npm run dev` есть дев-стенды:

- `http://localhost:5273/overlay-lab.html` — настоящий оверлей во фреймах
  в разных состояниях (`?place=town|offline&mode=&scale=&goal=&locked=1`);
- `http://localhost:5273/sound-lab.html` — звуки тем же движком, что и
  генератор, лестница ценности и «сессия фарма» — 20 секунд карты.
  Если локально лежит эталон для сравнения на слух
  (`out/poe2-edits/divine-space.wav`, папка вне Git), страница покажет
  кнопку A/B; в приложение и сборку эталон не попадает.

Тесты намеренно построены на реальных данных из логов, а не на выдуманных:
формат меняется каждый сезон, и только фикстуры из настоящих сессий ловят регрессии.

### Командная строка

```bash
npm run scan      # найти игру, разобрать все накопленные логи в data/gorn.db
npm run analyze -- "<путь>\UE_game.log"   # разбор одного файла
npm run sounds    # перерендерить звуки после правки рецептов в src/sfx/kit.ts
```

Повторный `scan` не создаёт дублей. Сохранять историю обязательно: игра
ротирует логи и удаляет старые бэкапы — на тестовой машине два файла исчезли
за один день.

Пример вывода `analyze` на реальной сессии:

```
═══ ЗАБЕГИ ═══
  всего зон        6
  из них фарм      2
  времени в картах 2 м 11 с
  получено ФЕ      44

═══ ФЕ В ЧАС ═══
  медиана          945 ФЕ/час
  среднее          945 ФЕ/час
  разброс P25–P75  473 — 1 418
  выборка          2 забегов (данных мало)
  ⚠ один забег дал 100% всего дохода — цифра держится на нём
```

Для тюрьмы в `src/cli/` лежат свои инструменты: `prison-replay` (прогон
сохранённых кадров), `prison-audit` (что пошло не так в забеге по кадрам
Горна), `prison-bench`, `prison-solve-bench` и `prison-tune` (замеры
и настройка стратегии). Запуск — `npx tsx src/cli/<имя>.ts`.

### Устройство

```
src/core/
  patterns.ts      регекспы и классификация протоколов
  eventParser.ts   строка лога → типизированное событие, разбор сокет-дампов
  inventory.ts     дельты слотов сумки  ← здесь живёт тонкость с Num
  runSegmenter.ts  нарезка потока на забеги
  priceStore.ts    референсные цены из ответов Торгового дома
  trade.ts         лоты, выплаты, коэффициент реализации
  retroScan.ts     разбор всех накопленных логов
  stats.ts         медиана, перцентили, достоверность выборки
  history.ts       история по дням и сессиям
  seasons.ts       сезоны и их номера в логе
  mapNames.ts      игровые названия карт по сцене и уровню
  bag.ts, csv.ts   стоимость сумки, экспорт для Excel
  i18n.ts          tr(ru, en) — перевод без ключей и библиотек
  format.ts        форматирование чисел, времени и длительностей
  plural.ts        русские склонения после числительных
  prison/          тюрьма: распознавание, движок правил, стратегия, решатель
src/storage/db.ts  SQLite (node:sqlite)
src/main/          Electron: движок, дочитывание лога, оверлей, обновления
  communityPrices.ts  первичные цены из базы сообщества TITrack
  prison/             поток экрана, воркер подсказок, слой стрелок
src/preload/       мост в renderer — только готовые срезы, без доступа к ФС
src/renderer/      интерфейс на React: окно, оверлей, плашки, стрелки тюрьмы
src/cli/           командная строка, генератор звуков, инструменты тюрьмы
src/sfx/           офлайн-DSP и рецепты звуков (рендер в WAV)
```

**Почему разбор в main-процессе.** ETor гнал в renderer сырые строки лога
тысячами и городил WebSocket-мост с подтверждением батчей, чтобы интерфейс
не захлёбывался. Здесь renderer получает готовые срезы: `Snapshot` с уже
посчитанными медианами и забегами. Доступа к файловой системе и Node у него
нет вообще.

### Справочники

**Предметы** — `data/items.json`, 2191 предмет SS14. Собирается скриптом
из выгрузки tlidb (входные файлы в репозиторий не кладутся):

```bash
node scripts/build-items.mjs <seed.json> [translations.json]
```

Свежую выгрузку к старту каждого сезона публикует TITrack (MIT) —
`tlidb_items_seed_en.json` в [их репозитории](https://github.com/astockman99/TITrack).
Русские названия — из словаря локализации [tlidb.com](https://tlidb.com)
со связкой по английскому названию; покрыто 2148 из 2191 (98%). Непокрытое
показывается по-английски, связанные варианты выводятся как «Связанный: …».
То, чего нет в словаре, дописывается руками в `data/names-ru.json` — сборка
этот файл уважает и никогда не перезаписывает. Переводы типов — из прежней
сборки и ручного `data/types-en.json`.

**Игра переиспользует id между сезонами**: фитили SS13 (10320–10322) в SS14
стали линейкой компасов Afterlight. Ручное название в `data/names-ru.json`
перекрывает словарь, поэтому к старту сезона его стоит сверить с заметками
выгрузки (`meta.revisions`).

**Карты** — `data/maps.json`, собирается `node scripts/build-maps.mjs`
из таблицы зон TITrack и русских страниц tlidb. Неизвестные сцены дописываются
в `data/maps-manual.json`, а не угадываются по пиньиню.

**Тюрьма** — тексты и конфиги клиента SS14 описаны в
[docs/prison/README.md](docs/prison/README.md): RU/EN, исходные таблицы,
версии архивов и воспроизводимые скрипты извлечения (`scripts/tli-*`).
Сами тексты издателя в репозиторий не кладутся — только манифест и числа,
перенесённые в `rules.md`. При работе над правилами сначала сверяться
с этими данными — повторное извлечение той же сборки не нужно.

### Известные пробелы

- **Часть сцен без названия карты** — например, `JH_YWMD_*`: для них
  показывается внутреннее имя.
- **У предмета 381040 Flawless Spine: Torqued нет иконки** — адреса нет
  в самой выгрузке.

## Правила игры

Пассивное чтение лог-файла — наименее рискованная категория инструментов: игру
не трогаем, память не читаем, автоматизации нет. Тем не менее в пользовательском
соглашении XD есть широкий пункт про стороннее ПО, формально покрывающий и оверлеи.
Сообщений о банах за трекеры не встречалось, но это терпимость, а не разрешение —
используешь на свой риск.

Чего в проекте не будет принципиально: любой автоматизации ввода, скрейпинга биржи
и любого взаимодействия с клиентом игры.
