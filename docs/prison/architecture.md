# Свой симулятор тюрьмы: архитектура

Свой симулятор вместо прежнего (код «Tartarus Simulator» без лицензии, с
версии 1.0 удалён): распознавание экрана, движок правил, стратегия и
проверка вариантами. Цель — подсказки в публичных сборках Горна при в разы
меньшей нагрузке: у прежнего ход стоил ~0,4 с распознавания и до 1,5 с
расчёта на ядре.

Правила игры — в [rules.md](rules.md).

## Источники правил

- Правила, шансы и механики берём **из любого источника**: тексты карт,
  свои кадры и замеры, гайды, вики, а также «Tartarus Simulator» — его
  код и данные (`rates.json`). Это решение пользователя
  от 2026-10-18: нам нужна информация, по которой работать, а лишние
  ограничения только мешают. В `rules.md` у факта пишем, откуда он.
- Код Горна свой: чужие файлы и функции в `src/` не переносим, а пишем по
  `rules.md`.
- Сравнивать **результаты** (тот же кадр или та же позиция → наш ответ
  против нынешнего) может любая сессия.
- Эталоны распознавания собираются своим инструментом из своих скриншотов.
- Чужого кода в репозитории нет: `vendor/tartarus` перед первым пушем
  вычищен из истории (распространять код без лицензии мы не можем).

## Модули

Всё новое лежит в `src/core/prison/`: чистый TypeScript без Electron, чтобы
гонять в тестах и в процессе подсказок.

```
src/core/prison/
  model.ts          ид и типы: звери, редкости, орудия, события, подарки, цели
  view.ts           что распознано на экране (ScreenView) — договор распознавания
  engine/           движок правил
    state.ts        состояние в типизированных массивах, копирование одним set()
    rng.ts          ГСЧ (один uint32), потоки по меткам
    rules.ts        кто кого ест, укус, утро, двери, события, орудия
    actions.ts      легальные ходы и их применение
  policy/           мгновенная стратегия: ход без перебора, оценка доски
  solver/           проверка вариантами: Монте-Карло, общие кости, ранняя остановка
  adapter.ts        ScreenView + память забега → состояние движка
  recognize/        распознавание
    geometry.ts     калибровка: где доска и панели при этом разрешении
    board.ts        камеры, надзиратель, двери, дни, ряд решений, цепочка, тропа
    panels.ts       орудия, призматические, цель
    pick.ts         выбор орудий, сокровищница
    templates/      эталоны (JSON), собранные scripts/prison-templates.mjs
scripts/prison-templates.mjs   сборка эталонов из размеченных кадров
test/prison/                   тесты: правила, стратегия, распознавание на кадрах
```

`src/main/prison/worker.ts` остаётся связкой: протокол
`PrisonShotMessage → PrisonWorkerReply` и метки на кадре не меняются.
С версии 1.0 путь один — свой симулятор.

## Договоры между частями

Номера камер внутри — **0–15**: 0 — допросная. Игроку показываем +1.

```ts
// model.ts
export type Beast = 'mammoth' | 'lion' | 'wolf' | 'rat';
export type Tier = 0 | 1 | 2 | 3 | 4 | 5; // Обычная … Призматическая
export type ToolId = 'forged' | 'keys' | 'dogtag' | /* … 31 шт., см. rules.md §7 */ 'trap';
export type GiftId = 'ring' | 'horn' | 'wine' | 'brand';

// view.ts — выход распознавания
export interface CellView {
  kind: 'office' | 'locked' | 'empty' | 'inmate';
  beast?: Beast;
  tier?: Tier;
  event?: boolean;     // «!»
  nest?: boolean;
  jaws?: boolean;      // цель пожирания на экране цепочки
  shownTier?: Tier;    // редкость видна на запертой двери
}
export type Box = [x0: number, y0: number, x1: number, y1: number]; // пиксели кадра
export interface BoardView {
  cells: CellView[];               // 16
  warden: number | null;
  daysLeft: number | null;
  doors: number[];                 // предложенные камеры, в порядке карточек
  decision: null
    | { kind: 'manage'; consume: boolean; replace: boolean; end: boolean }
    | { kind: 'office' }
    | { kind: 'ratway' }             // «Выберите цель»
    | { kind: 'event' };             // окно события
  chain: { targets: number[] } | null; // «Выберите узника для пожирания»
  tools: ToolId[];
  chromatic: number;               // призматических в хранилище
  objective: string | null;
  at: {                            // где рисовать метки
    cells: { x: number; y: number; r: number }[];
    doorCards: Box[];
    decisionCards: Box[];
    cancel: Box | null;
  };
}
export interface PickView { cards: (ToolId | null)[]; boxes: Box[]; reroll: boolean; reward: boolean }
export type ScreenView =
  | { screen: 'board'; board: BoardView }
  | { screen: 'pick'; pick: PickView }
  | { screen: 'treasure'; gifts: Box[] }
  | { screen: 'other' };

// recognize
export interface Frame { width: number; height: number; data: Uint8ClampedArray } // RGBA
export function calibrate(frame: Frame): Geometry | null;             // редко: первая доска, смена разрешения
export function read(frame: Frame, geo: Geometry | null): { view: ScreenView; geo: Geometry | null };

// engine
export type Action =
  | { type: 'patrol'; cell: number } | { type: 'devour'; to: number } | { type: 'chain'; to: number }
  | { type: 'stopchain' } | { type: 'swap' } | { type: 'end' } | { type: 'hunt'; to: number }
  | { type: 'office'; choice: 'bestow' | 'instigate' } | { type: 'event'; accept: boolean }
  | { type: 'choose'; id: ToolId | GiftId } | { type: 'reroll' };
export interface Engine {
  legal(s: State): Action[];
  apply(s: State, a: Action, rng: Rng): void;     // на месте, без аллокаций
  copy(from: State, to: State): void;
  score(s: State): number;                        // призматических в хранилище
}
// горячий путь: ход — целое (вид << 6 | аргумент), буфер переиспользуется
export function legalCodes(s: State, out: Int32Array): number;
export function applyCode(s: State, code: number, rng: Rng, p: Params): void;
export function randomPlayout(s: State, rng: Rng, p: Params, buf: Int32Array): number;

// policy / solver
export function instant(s: State): Action;
export function solve(s: State, opts: { seed: number; minRounds: number; maxRounds: number }):
  { step(ms: number): { best: Action; options: { action: Action; mean: number; gapSe: number }[]; done: boolean } };
```

## Стратегия и проверка вариантами (этап C)

**Мгновенная стратегия** (`policy/instant.ts`): доска оценивается суммой
ценностей узников по редкости (смешение «начало / конец забега» по
оставшимся дням) плюс подарки, двери, события и «есть еда». Пожирание
считается точно: едок в цепочке идёт только вверх по редкости, а съеденный
всегда ниже следующей ступени, так что матожидание цепочки зависит лишь
от (редкость, зверь, укус в цепочке) и состава доски — таблица 6 × 4 × 2,
заполняется сверху вниз без аллокаций. Из неё же — ценность двери
(ожидаемый узник по шансам и его действие сегодня), «Отменить», замена
против пожирания. Подарки и события — пробным применением на копии.
Стратегия видит только показанное игроку. `advise()` даёт ход и подпись
≤ 40 символов.

**Веса** (`policy/weights.json`) настроены `npx tsx src/cli/prison-tune.ts`:
покоординатный поиск, 20 000 забегов на оценку, все кандидаты на одних
забегах, шаг принимается при выигрыше ≥ 2 SE парной разницы. Отчёт —
`--report`, 20 000 других забегов на клетку, среднее призматических:

| Сценарий | Случайные | Жадная | Ручные веса | Настроенные |
|---|---|---|---|---|
| все стартовые события поровну, выбор орудий | 0,82 | 2,66 | 4,56 | 7,31 |
| без орудий (без выбора и без целей) | 0,07 | 0,69 | 1,03 | 1,24 |
| двери: связка, поддельный ключ, короткая цепь | 0,44 | 2,10 | 3,05 | 4,86 |
| пожирание: плеть, ошейник, пила, корона | 1,44 | 5,32 | 5,70 | 6,94 |
| замена: петля, столб, пест, секира | 0,84 | 2,80 | 4,94 | 6,29 |
| утро: монета, удушающая цепь, капкан | 2,35 | 4,13 | 4,94 | 6,38 |
| старт: нет | 0,39 | 1,72 | 2,60 | 4,74 |
| старт: Бой в клетке | 1,60 | 4,01 | 4,96 | 7,12 |
| старт: Железный закон (30 дней) | 0,97 | 3,69 | 5,42 | 8,48 |
| старт: Тирания | 0,62 | 1,82 | 4,52 | 7,43 |
| старт: Изобилие | 0,53 | 2,05 | 5,38 | 8,75 |

Числа — на нашем движке с его допущениями (rules.md §11): сила против
живой игры станет известна только после сверки правил.

**Проверка вариантами** (`solver/solve.ts`): Монте-Карло по ходам-кандидатам,
доигрывание мгновенной стратегией. Скрытое (неоткрытые двери, невидимые
закреплённые узники, виды событий за «!» — по весам движка `eventWeight`)
перебрасывается на каждый раунд одинаково для всех кандидатов. Кости общие: ГСЧ перезаправляется от
(раунд, день, фаза, номер решения за день) и каждое утро — после разных
ходов будущее кандидатов снова совпадает; это сократило p95 времени в
полтора раза. Остановка: каждый соперник ≥ 3 SE позади либо разница +
2 SE < 0,1; ≥ 4 SE позади — отсекается. Тот же кадр (ключ — хеш
состояния) продолжает накопленный поиск.

Замер `npx tsx src/cli/prison-solve-bench.ts` (2026-10-18, Ryzen 7 7800X3D,
один поток): 438 позиций из 12 забегов самоигры, раунды 64…1500 —
мгновенный совет 2 мкс (p95 8 мкс), проверка до остановки медиана 18 мс,
p95 233 мс, max 738 мс; в потолок упёрлись 0,7 %. Проверка сменила
мгновенный совет в 44 % позиций (обход 58 %, выбор 55 %, ряд решений 37 %,
цепочка 35 %, события 3 %). Игра целиком (`--play`, 120 одинаковых
забегов, проверка ≤ 300 мс на ход): 9,35 призм. против 7,13 у мгновенной,
+2,2 ± 0,3.

## Проверка

- **Правила** — unit-тесты на каждое правило из `rules.md`, с фиксированным ГСЧ.
- **Распознавание** — точность по полям на `Documents/gorn-prison-data`.
  Без этой папки тест пропускается, в CI его нет. Порог — паритет: сейчас
  100 % на `boards-ru4k.json`. Плюс скорость на кадрах из
  `Изображения/Горн — тюрьма`.
- **Стратегия** — самоигра: среднее число призматических за забег на одном
  наборе забегов. Сравнение с нынешним решателем по совпадению ходов делает
  основная сессия.
- **Живые замеры** — по своим кадрам с логом сверять догадки из `rules.md`.

## Распознавание (этап B)

Всё — выборка маленьких областей кадра в опорных координатах 1920×1080
(`layout.ts`) и сравнение нормированных картинок с прототипами
(скалярное произведение). Кадр целиком не копируется и не масштабируется.

- **Геометрия** (`geometry.ts`): масштаб и сдвиг опорной разметки. Сначала
  место «по высоте кадра», проверка — подписи номеров камер 1–16. Не нашлось —
  карта перепадов яркости (стены и рамка доски, среднее по 358 кадрам) на
  сетке 16 и 8 опорных px, 9 масштабов интерфейса 70–110 %, сдвиг до ±15 %
  кадра; затем точная подгонка по найденным подписям (наименьшие квадраты).
  Проверено на 1920×1080, 2000×1125, 3840×2160, 2560×1440, 1280×720, 21:9 и
  интерфейсе 85–90 %. Геометрия сохраняется между запусками; при том же
  размере кадра без подписей на месте экран — «другой», но если доску ждут
  (кадр доски по логу, хоткей) или прежняя геометрия промахнулась
  `GEO_MISSES` (3) кадра подряд, доска ищется заново: масштаб интерфейса и
  режим окна меняются без смены разрешения.
- **Камеры** (`cells.ts`, `board.ts`): замок — эталон-среднее; портрет —
  прототипы k-средних по классам (4 зверя, «?», пустая запертая); редкость —
  оттенок рамки портрета (серебро / синий / фиолет / тёплый), Легендарную и
  Величайшую различает цвет пламени вокруг (оранжевое / красное), радужную —
  зелёное в свечении; клыки — эталон; «!» — доля оранжевого справа от
  замка; надзиратель — золото стрелки у камеры.
- **Текст** (`text.ts`, `cards.ts`): дни и номера дверей — разбивка строки на
  знаки по столбцам, цифры по эталонам с кадров (дни), «№» и буквы
  отсекаются по высоте и строке. Двери вне 1–6 шагов от надзирателя
  отбрасываются.
- **Панели и экраны** (`panels.ts`, `pick.ts`): надпись над карточками,
  значки решений, орудия на панели, места хранилища, цель, карты выбора
  (картинка + название), сокровищница — прототипы своих размеченных кадров.

Эталоны собирает `node --import tsx scripts/prison-templates.mjs` из
`Documents/gorn-prison-data` (кадры Горна скопированы в `images/gorn`:
папка «Горн — тюрьма» чистится). Набор `boards-ru4k.json` в сборку не идёт.

Разметка, сделанная на этапе B (в папке данных, `labels/`):
`gorn-cells.json` (5 182 камеры), `gorn-screens.json` (надпись, дни,
карточки, орудия, хранилище, цель), `gorn-picks.json` (22 экрана выбора),
`gorn-new-screens.json`, `screens-ru.json` (тип экрана и фаза на ru/ru4k).
Всё собрано кластеризацией и проверено глазами по миниатюрам.

Точность (`test/prison/recognize.test.ts`): `boards-ru4k.json` — 100 % по
всем полям (6 досок, 90 камер); `boards-ru.json` — 100 %; выбор орудий
`picks-panels-digits.json` — 10/10; панели и цифры — 100 %; кадры Горна —
100 % по 5 182 камерам и всем полям экрана (это обучающий набор).

Не сделано, нет кадров:

- **гнездо** (Шевелящийся железный ящик) — ни одного кадра, `nest` не
  ставится;
- **окно события** — закрывает доску целиком, `screen: 'other'`;
  `decision: { kind: 'event' }` не выдаётся. Совет там и не нужен: у окна
  одна кнопка «Подтвердить» (rules.md §8), а вид события решатель
  перебрасывает по весам движка;
- **крысиная тропа** («Выберите цель») — всего 2 кадра (ru/09, ru4k-09);
- **редкость на запертой двери** (`shownTier`) — читается, но размеченных
  кадров нет;
- **орудия на панели** — эталоны для 26 из 31, нет forged, dogtag,
  guillotine, pestle, claws: в своих кадрах их ни разу не брали (проверка
  20.10 по 1 591 кадру Горна и 562 снимкам экрана). Карты выбора — для всех
  31. Незнакомая иконка на панели — место `null`, список дальше читается.
  Пока эталонов нет, адаптер не записывает «предположительно» посоветованное,
  если в выборе было такое орудие, а неузнанную иконку объясняет орудием
  без эталона из памяти (иначе одно такое орудие выключало забывание
  чужих орудий навсегда). Набор орудий с эталоном берётся из самих
  эталонов (`panelToolIds`) — новые иконки снимают ограничение сами;
- **третья строка панели орудий** (5+ орудий) — место выведено по шагу, не
  проверено.

## Связка с Горном (этап D)

- `adapter.ts` — память забега между кадрами (`RunMemory`, обычный JSON:
  сохраняется ответом `'state'` в `prison-state-own.json`) и позиция
  движка по ней. Помнит то, чего не видно на одном кадре: орудия (на
  экране цепочки панели нет), цель, день и лимит (больше 20 дней осталось
  — «Железный закон»), хранилище, доску до затемнения цепочки, сколько
  подарков подряд. Экран «Выберите узника для пожирания» до первого укуса
  — ещё выбор Пожирания («Отменить» ведёт к Замене или концу дня), после
  укуса — цепочка. Неоткрытые двери и виды событий не закрепляются —
  решатель их перебрасывает. Ход, которого нет на экране (нет карточки
  «Замена»), не советуется.
- `hint.ts` — ход → текст и метки по `BoardView.at` (с `decisionKinds`),
  `PickView.boxes`, местам подарков и «Обновить» по геометрии.

## Порядок работ

| Этап | Что | Зависит от | Срок |
|---|---|---|---|
| A | Движок: `model.ts`, `engine/`, тесты правил | rules.md | ~2 недели |
| B | Распознавание: `view.ts`, `recognize/`, сборка эталонов, тест точности | данные | 3–4 недели |
| C | Стратегия и проверка вариантами, самоигра | A | 2–3 недели |
| D | `adapter.ts`, переключатель в `worker.ts`, сравнение с прежним, удаление `vendor` | A, B, C | ~1 неделя |

A и B независимы, их ведут две отдельные сессии, каждая в своём worktree.
`model.ts` пишет этап A, `view.ts` — этап B. Общие имена (`Beast`, `Tier`,
`ToolId`) у обоих берутся из этого документа, при слиянии сводятся в
`model.ts`.
