# Тюрьма Талоса (сезон 14): правила для своего симулятора

Спецификация правил мини-игры «Тюрьма Талоса» (внутреннее имя клиента —
S16Gameplay) из Torchlight: Infinite, по которой Горн строит свой движок.
Правила пересказаны своими словами; полные тексты клиента — у издателя и в
git не хранятся (см. «Источники»).

Метки надёжности:

- **[клиент N]** — запись N клиента игры: текст орудия, события, цели или
  числовой конфиг. Текст подтверждает формулировку, но не порядок
  срабатывания и не состав серверного пула;
- **[таблица N]** — числовое поле записи N в расшифрованных Lua-таблицах
  клиента (Weight, SpawnCellState, Exclude и др.). Это базовые значения;
  как сервер применяет их в забеге, клиент не показывает;
- **[глоссарий N]** — термин-гиперссылка клиента (он же словарь tlidb);
- **[кадры]** — видно на своих кадрах русского клиента;
- **[замер]** — измерено по живым забегам, с числом наблюдений;
- **[догадка]** — ни в клиенте, ни в замерах не найдено.

Где правило — догадка, в движке оно настраивается параметром (`Params`,
`src/core/prison/model.ts`), а не зашивается в код.

## 1. Поле

- Кольцо из 16 камер [клиент config 301], номера 1–16 по часовой стрелке.
  Камера 1 — **допросная** [клиент config 303]: в ней не бывает узников, она
  никогда не заперта.
- Соседи камеры — номера ±1 по кольцу. Расстояние — шаги по часовой
  стрелке, `(b − a + 16) mod 16`.
- **Надзиратель** начинает в допросной [клиент config 302].
- В начале забега **4 случайные камеры открыты**, остальные заперты
  [клиент config 309; кадры 17.10 и 18.10: 4 в 16 забегах из 17, в оставшемся
  стартовая Монета убрала узника в первое утро]. Доску за стартовым выбором
  орудия не видно, движок разыгрывает её в первое утро (`START_PENDING`).
- На поле всегда **не меньше одной метки события** [клиент config 310].
  Метка «!» стоит и над запертой, и над открытой камерой [кадры]; у каждого
  события своё допустимое состояние камеры (раздел 8). **Добор — сразу,
  как сработала последняя метка, а не утром** [замер 19.10: в логе 125 из
  127 появлений метки — сразу после «Подтвердить» в окне события, утром ни
  одного; на кадрах во всех 206 чистых доборах перед этим была ровно одна
  метка]. **Камера — случайная среди камер без события, кроме допросной и
  камеры надзирателя** [замер 19.10, 206 доборов: на запертую 100 при
  ожидании 103,4 для равномерного выбора; по шагам от надзирателя
  χ² = 16,9 при пороге 23,7; в камеру надзирателя — ни разу]. Затем
  событие, допустимое для неё (`eventMin`). Прежний замер «событие за
  6,4 % дверей первого дня» с этим сходится: одна метка на 15 камер — 6,7 %.
- «Открыть» камеру — сделать её открытой и показать кодовое имя и редкость
  узника [глоссарий 16000102].

## 2. Узники

- Кодовые имена: Слон, Яростный лев, Вожак, Огромная крыса
  [глоссарий 16000104]. В движке — мамонт, лев, волк, крыса.
- Редкости: Обычная (0), Магическая (1), Редкая (2), Легендарная (3),
  Величайшая (4), Призматическая (5).
- Призматический уходит в **хранилище**, его камера снова запирается. Очки
  забега — число призматических. Мест 10 [клиент config 114]. При полном
  хранилище рост стоит на Величайшей [со слов игрока].
- «Идентичные» — одинаковые кодовое имя и редкость; «Высший» / «Низший» —
  выше / ниже по редкости, чем текущий [глоссарий 16000110–16000112].
- При равенстве «наивысшей редкости» выбирается случайный
  [глоссарий 16000121]. «Дефицитное» кодовое имя — у наименьшего числа
  узников на поле, считая нули; при равенстве случайное [глоссарий 16000120].
- «Разведка» показывает редкость за дверью, не открывая её; потом редкость
  может измениться от орудий и событий [глоссарий 16000119]. Движок
  закрепляет узника за дверью при разведке. [догадка]

## 3. День

Забег — 20 дней («Железный закон» — 30) [клиент 303].

1. **Утро.** Утренние орудия (раздел 7), добор меток событий, затем
   **пункты назначения** — карточки «Пойти в №N» / «Пойти в допросную».
2. **Пункты назначения.** Кандидатов броска — 3, значение броска — от 1 до
   6 шагов [клиент config 305–307]. Карточки — **три разных числа шагов из
   1–6**, без повторов, все числа поровну [замер 19.10, кадры: 548 утр из 549
   с тремя разными шагами; шаги 1–6 — 256…290 раз каждый; все 20 сочетаний
   встречаются]. Поддельный ключ, Шипастая плеть и Столб для сожжения
   убирают по варианту [клиент 116, 106, 126]. **Без них карточек всегда
   три** [замер 19.10: 514 утр из 515]; прежний замер «в 16,9 % из 8 592 утр
   на одну меньше» не подтвердился, `oneLessDoor` = 0. Меньше одной карточки
   движок не даёт [догадка].
3. **Обход.** Надзиратель идёт по часовой стрелке. Запертая камера
   назначения открывается; если в ней событие, открывается окно события.
   Допросная — раздел 5.
4. **Действие в камере надзирателя** («Примите решение»), одно в день:
   **Пожирание** (раздел 4), **Заменить** (раздел 6), **Выслеживание** —
   только с Окровавленным капканом в камере льва [клиент 143],
   **Завершить**. Пожирание и Замена в один день исключают друг друга.
   Выслеживание в движке тоже тратит действие дня [догадка].
5. Когда дни кончились, забег окончен.

## 4. Пожирание

Узник съедает узника **той же редкости**, над которым имеет
**преимущество**, получает +1 к редкости и случайное новое кодовое имя
[глоссарий 16000100; клиент config 311 = 1].

- **Преимущество** [глоссарий 16000107]: слон — над львом и вожаком; лев —
  над вожаком и крысой; вожак — над крысой; крыса — над слоном. Вторая еда
  (мамонт → волк, лев → крыса) — на любой редкости; это подтверждают и
  размеченные кадры.
- Призматический никого не ест.
- После укуса зверь едока меняется равновероятно среди четырёх, может
  остаться прежним [замер: сменился в 73 % из 141].
- **Цепочка** («Цепное пожирание»): если у едока с новым зверем есть цели,
  игрок ест дальше или отменяет [кадры].
- Каждый укус цепочки — отдельное Пожирание: клиент 103 говорит о «цепном
  Пожирании». Поэтому цель «Закон джунглей» считает каждый укус, а орудия
  «после Пожирания» (104, 106, 107) срабатывают после каждого укуса
  [догадка по тексту].
- **Подавление** [глоссарий 16000117]: повышение решается по разнице
  редкостей, за каждый ранг разницы шанс −5 %. Срабатывает после поедания
  Гильотиной с волчьими клыками [клиент 146]. Базовый шанс — 100 %
  [догадка], `oppressStep`.

## 5. Допросная

Пришёл в допросную — выбрать одно из двух:

- **Наградить** — повысить редкость одного случайного узника
  [глоссарий 16000109]; на +1 [догадка].
- **Подстрекнуть** — добавить одно тюремное событие в случайную камеру
  [глоссарий 16000108; игрок: ровно одно]. Движок выбирает любую камеру без
  события, открытую или запертую, и событие, допустимое для неё
  [догадка: камеру с событием не выбирает].

## 7. Орудия пыток (31)

Действуют до конца забега [глоссарий 16000105]. Выбор в начале и за
каждую выполненную цель — 3 варианта [клиент config 320].

**Какие орудия выпадают** [таблица relic 101–148]:

- базовый Weight: **40** у обычных (101–132), **5** у особых (141–148);
- MaxObtain 1: имеющееся орудие не выпадает;
- Exclude: особые орудия совместимы только с парой своего зверя (141/142
  слон, 143/144 лев, 145/146 вожак, 147/148 крыса), остальные особые при
  них не выпадают; у обычных исключений нет;
- BuildWeightInc — 40 у обычных, 0 у 131/132, 80 у особых (по BuildID).
  Как сервер прибавляет его к весу — не найдено, движок его не применяет.
  **К каждому выбору он не прибавляется**: особых орудий на своих кадрах
  выбора 20 из 354 карт (5,6 %); по базовым весам ожидается около 4 %, с
  прибавкой BuildWeightInc — около 27 % [замер 19.10, 122 расклада]. Может
  действовать по условию (например, при орудиях того же BuildID) — не
  проверено;
- UnlockType 402 (число завершённых забегов), UnlockParam 1 у обычных и 5
  у особых. Прогресс аккаунта движку неизвестен — [допущение: всё
  разблокировано].

Движок выбирает 3 разных орудия взвешенно без возвращения среди
допустимых — это **приближение по базовым весам**: динамические поправки
и момент применения исключений у сервера не найдены. Поля
OneTurnTriggerLimit / TotalTriggerLimit у всех 0, их смысл не установлен;
движок их не трактует ни как запрет, ни как отсутствие предела. Priority
есть у всех орудий, но планировщика по нему в клиенте не найдено — порядок
срабатывания по нему не переставлялся.

**Обновление выбора** («Осталось раз»): атрибуты забега 35 / 36 — всего и
использовано обновлений, интерфейс показывает `max(0, attr35 − attr36)`
по присланным сервером значениям [клиент S16BoardModel]; обновления от
питомца общие на забег [глоссарий 16000106]. InitValue 0 у атрибутов 35/36
не значит, что обновлений нет. **Базовое число — одно на забег, между
выборами не восстанавливается** [замер 19.10]: в логе за 27 забегов
(`Btn_S16Board_RelicPop_Reroll`) двух обновлений за забег не было ни разу;
на кадрах кнопка «Обновить» пропадает после нажатия, и если обновили на
старте, на выборе в награду её нет в 9 забегах из 10. Питомца у игрока,
судя по этому, нет — его прибавку так не проверить. Питомец «Двойные инквизиторы» даёт
ещё +1 с шансом 50 % (ур. 2–3) или 100 % (ур. 4–6) [патч-ноут SS14, tlidb].

«Без других эффектов» — в тексте клиента есть оговорка, что открытие не
запускает других эффектов. В графе «Движок» — где правило из текста, а где
толкование.

## 11. Чего не знаем

### Где это искать

- **Исходы считает сервер, но веса есть в клиенте.** Клиент шлёт выбор
  (`S16WardenResolveChoiceReq`), сервер присылает готовые изменения доски
  по порядку (`S16WardenChangeNotify` → `changeDetails` с `sequence`) и
  историю (`S16WardenGetHistoryReq`); найденный клиентский код исходов не
  считает. Базовые веса событий, орудий, целей и тем лежат в клиентских
  таблицах (разделы 7, 8, 10). Распределения редкости при открытии и
  Замене, шансы меток по дням и тела эффектов (EffectId) в исследованном
  наборе не найдены; общий и нативный код клиента полностью не
  исследовались. В `UE_game.log` сообщения сервера не пишутся.
- **Звуки интерфейса в логе.** Клиент пишет каждый звук
  (`AudioMgr@PlayAudio AudioEnum == UI_S16_…`) и каждое нажатие
  (`UIButton@ normal-click Btn_S16…`), и по ним видно многое из того, что
  присылает сервер [клиент S16Cell, S16BoardCell, S16BoardRelicPop,
  config event]:
  - `Basic_Quality` / `Mid_Quality` / `Premium_Quality` — показ редкости
    узника: Обычная–Редкая / Легендарная–Величайшая / Призматическая. Чистое
    открытие запертой камеры — только звук редкости; смена узника в открытой
    камере — сначала `Piece_Disp`, затем звук; укус — `Prison_Relock`
    (камера съеденного запирается);
  - `Prison_Exclamation_point` — на камере появилась метка события (при
    загрузке доски не звучит);
  - `Prison_Incident_Window_<код>` — окно события: AXCZ — 203, YFTX — 213,
    XB — 232, LSFY — 242, CXXL — 222, JY4 — 255, `Gen` — остальные;
  - `Torture_Click_Reset` — «Обновить» в выборе орудий; `Torture_Effect` —
    срабатывание орудия на панели; `Prison_Task_Done` — цель выполнена;
  - `Cell_Light` звучит не на каждую карточку утра: число карточек по нему
    не посчитать, оно берётся с кадров.

  Игра хранит только последние несколько логов, поэтому для массовых
  замеров их нужно сохранять заранее.
- **Таблицы `.out`** (`\x01XFC`) расшифрованы публичным декодером
  Sembiance/tli-extract (commit `f88a6e9e7a26a3da380a6fed77b1c243c200d42e`)
  без анализа исполняемого файла игры. Из 60 декомпилированных модулей 2 не
  проходят проверку синтаксиса, в сложных ветвлениях бывают артефакты
  декомпиляции; семь таблиц проверены отдельно и надёжнее.
- **«Журнал Талоса»** (`S16BoardLogPop`): найдена цепочка
  `Btn_S16Board_Bottom_Log` → `OnLog` → `S16BoardLogPop`, но

Порядок по важности для движка.

1. Шансы редкости при открытии и при Замене в клиенте не найдены; замеры —

   откуда берутся вторые метки в начале дня (14 из 215).
